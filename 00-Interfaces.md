## 3. Signing domains (domain separation)

Every badge signature is over `prefix || bytes`. The firmware enforces which prefixes need a button press.

| Prefix | Signed bytes | Button required | Who calls |
| --- | --- | --- | --- |
| *(none — raw Solana message)* | serialized Solana transaction message | **Yes** | payer, via `wallet.sign_solana` |
| `bank-auth:` | canonical bank payload (§6) | **Yes** | payer, via `wallet.sign_bank` |
| `pay-req:` | REQ body (§5) | No (auto) | payee, via `wallet.sign_request` |
| `pay-proof:` | `req_id ‖ nonce ‖ payer_pubkey` | No (auto) | payee, via `wallet.sign_proof` |
| `registry:` | registry record (§7) | — (issuer key on laptop, never on a badge) | backend |

The raw Solana message cannot collide with a prefixed message because a Solana message starts with its header bytes, never with ASCII `pay-`/`bank-`. Firmware must still refuse to sign raw bytes that begin with any of the prefixes above.

## 4. Lua wallet API (implemented by A, used by everyone)

```lua
-- identity
wallet.pubkey()            --> 32-byte string
wallet.address()           --> base58 string
wallet.key_location()      --> "se050" | "nvs"

-- presence (payer side)
wallet.new_nonce()         --> 16-byte string; firmware stores it + start time
wallet.check_proof(req_id, payee_pubkey, proof_sig)
                           --> "present" | "late" | "bad_sig" | "no_nonce"
                           -- firmware checks sig over pay-proof:req_id||nonce||own_pubkey
                           -- and that it arrived within PRESENCE_DEADLINE_MS

-- presence (payee side)
wallet.sign_request(req_body_bytes)            --> 64-byte sig (auto)
wallet.sign_proof(req_id, nonce, payer_pubkey) --> 64-byte sig (auto)

-- registry
wallet.check_record(record_bytes, issuer_sig)
                           --> table {ok=bool, reason=?, display_name, device_pubkey,
                           --         kind, solana_wallet, bank_ref_hash, expiry, status}
                           -- firmware verifies issuer sig against the PINNED issuer key,
                           -- expiry, status, freshness (issued_at within RECORD_TTL_S)

-- signing with approval (BLOCKS until SELECT / CANCEL / timeout)
wallet.sign_solana(msg_bytes, ctx)  --> sig | nil, reason
wallet.sign_bank(payload_str, ctx)  --> sig | nil, reason
-- ctx = { record = <record_bytes>, record_sig = <sig>, presence = "present"|"late"|... }
-- reason ∈ "cancelled" | "timeout" | "undecodable" | "payee_mismatch" | "over_cap"
```

Approval-screen rules (firmware, not Lua):
- Amount, token/currency and recipient come **only from the decoded bytes**, never from `ctx`.
- Verified state comes **only from `wallet.check_record`** run inside the firmware on `ctx.record`.
- If the decoded recipient ≠ `record.solana_wallet` (Solana) or decoded `payee_ref` ≠ `record.bank_ref_hash` (bank) → red **MISMATCH**, SELECT disabled.
- States: green ✓ verified + ● present; amber = verified but not present / late; red = unverified, revoked, expired or mismatch.

Constants owned by A, tuned with R's measurements: `PRESENCE_DEADLINE_MS` (start 250), `RECORD_TTL_S` (start 120), `APPROVAL_TIMEOUT_S` (start 60), `SPEND_CAP` (P2).

## 5. ESP-NOW messages (binary, little-endian)

Common header (4 B): `magic "VK"` (2) · `version u8 = 1` · `type u8`

| Type | Name | Body after header | Size |
| --- | --- | --- | --- |
| 1 | REQ | `rail u8` (1=solana, 2=bank) · `payee_pubkey [32]` · `amount u64` (minor units) · `currency [4]` ("USDC" / "USD\0") · `req_id [8]` · `expiry u32` (unix s) · `name_len u8` · `name [≤32]` · `sig [64]` over `pay-req:` + everything from header to name | ≤ 158 B |
| 2 | CHAL | `req_id [8]` · `nonce [16]` · `payer_pubkey [32]` | 60 B |
| 3 | PROOF | `req_id [8]` · `sig [64]` over `pay-proof:` ‖ req_id ‖ nonce ‖ payer_pubkey | 76 B |
| 4 | RESULT | `req_id [8]` · `status u8` (0=ok, 1=rejected, 2=failed) · `ref [64]` (Solana tx sig or Nessie id, zero-padded) | 77 B |

REQ is broadcast; CHAL/PROOF/RESULT are unicast to the sender's MAC. The REQ name is a *claim*: display only after `wallet.check_record` confirms it.

## 6. Bank authorization payload

UTF-8, `key=value` per line, `\n` separated, **exactly this order**, no trailing newline. Signed bytes = `bank-auth:` + payload.

```
v=1
rail=nessie
action=purchase|transfer
amount_cents=4000
currency=USD
from_acct=<payer Nessie account id>
payee_name=<record.display_name>
payee_ref=<hex record.bank_ref_hash>
attestation=<SAS attestation address>
proof_nonce=<hex 16 B nonce from the handshake>
issued_at=<unix seconds>
```

## 7. Registry record (what the badge verifies)

Served by `GET /registry/:pubkey`; the backend builds it from the on-chain SAS attestation and signs it with the issuer key. Canonical bytes = same `key=value\n` style:

```
v=1
attestation=<address>
display_name=<≤32 chars>
device_pubkey=<hex 32>
kind=merchant|person
solana_wallet=<hex 32 or empty>
bank_ref_hash=<hex 32 or empty>
expiry=<unix s>
status=active|revoked
issued_at=<unix s>
```

Response JSON: `{ "record": "<base64 canonical bytes>", "sig": "<base64 64 B>" }`. A revoked or unknown key returns a signed record with `status=revoked` or HTTP 404 (badge treats 404 as unverified).

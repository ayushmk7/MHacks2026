# os/test: host tests and device tests

Two kinds of test. The full specification, with every suite and every acceptance test, is [docs/os/testing/testing.md](../../docs/os/testing/testing.md).

## host/: on the laptop, no badge

Plain C99 and C++17 built with the laptop's compiler, no Arduino. They cover the pure code (`src/vk/wallet/pure/`, the keyboard and power logic), the state machines and stores (approval, config, manifest, consent, history, contacts, requests, Wi-Fi), and `lib/vk.lua` (when a `lua` binary is installed).

```bash
cd os
test/host/run.sh              # every suite; exit status 0 only if all pass
test/host/run.sh sol record   # only these suites
```

- A suite is `test_<name>.c`, `test_<name>.cpp` or `test_<name>.lua`, prints `all <name> tests passed` as its last line and exits 0. A C or C++ suite names the firmware files it links in a `// LINK:` comment in its first five lines.
- `shim/` is a minimal `Arduino.h`, `Preferences` and file layer for the C++ suites; `host_ed25519.c` is the laptop's Ed25519.
- `vectors.json` and `vectors.h` are generated by `vectors.mjs` (with `node` from `dashboard/`) and shared with the device tests.
- Build output goes to `test/host/build/` (ignored by git). `scripts/preflash-check.sh` runs the host suites before every build.

## device/: on a badge, over USB serial

Python scripts driven by `scripts/vkdev.py`, against a badge running the **dev** build (it has the test commands: `VKBTN`, `VKSTATE`, `VKSHOT`, ...).

```bash
cd os
../.venv/bin/python scripts/vkdev.py --port /dev/cu.usbserial-XX test test/device/t_boot.py test/device/t_shell.py
../.venv/bin/python scripts/vkdev.py --port P --port2 P2 test test/device/t_req.py --include-deferred   # two badges
```

- A test is `t_<name>.py` with `def run(badge):` (or `def run(badge, badge2):`). User apps have `t_app_<id>.py`.
- A test that needs a second badge, the network or a person declares `NEEDS = "two-badges"`, `"network"` or `"hands"`; `vkdev.py test` skips it unless `--include-deferred` is given. A two-badge test takes `run(badge, badge2)` and needs `--port2`. By name, `_2` marks a two-badge test, `_net` a network one and `_single` the one-badge half of a two-badge test.
- `common.py` holds shared helpers; `fixtures.py` builds transfer messages, registry records and requests on the laptop with the test keys of `host/vectors.json` (`python fixtures.py` self-checks them; needs `cryptography`). `fixtures/` holds small apps that `t_app.py` and `t_hook.py` push (one per manifest case: `plain`, `noperm`, `needsign`, `nonet`, `minapi99`).
- `shots/` holds the screenshots the tests save, named `<screen or case>_<theme>.png`; they are kept in git as the visual record.
- `vkdev.py test` ends by removing any app it pushed that is not in `os/apps/` (`tidy`), so a test run leaves the launcher as it was.

## Keep testing lean

Run what a change touches, not the whole regression: the host suite of the module you changed, plus the device tests of the screens and apps you changed (the commit or status note names them). The full device regression is for a release candidate and costs a badge for a long time; a reset over serial can also leave the badge's buttons dead until a power cycle ([the I²C log](../../docs/logs/BADGE-BUTTONS-I2C.md)).
